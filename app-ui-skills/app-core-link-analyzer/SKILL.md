# App 核心链路分析

把设备上的真实界面、原型和需求归一成同一份上下文，输出下游可直接消费的链路清单，并让每个节点落到具体页面——App 没有 URL 可抄，只有导航路径。

## 输入

| 来源 | 说明 | 用途 |
| :--- | :--- | :--- |
| 安装包 / 小程序 | apk、ipa（TestFlight 或企业签名）、小程序体验码；含版本号 | 取实际形态：入口 tab、页面标题、控件与按钮文案、默认值、必填标记、权限弹窗 |
| 运行环境 | 真机或模拟器的型号、系统版本、分辨率，是否具备定位、蓝牙、相机等硬件能力 | 决定哪些节点能实测，哪些只能看原型 |
| 原型图 | 截图、蓝湖或 Figma 链接、原型文字描述 | 取设计意图、字段约束、交互态 |
| 需求材料 | PRD、需求说明、状态机、车辆或设备绑定规则 | 取业务口径：角色、规则、状态定义 |

### 取数

先取到内容再谈分析。按下表取数，并把「实测 / 录屏 / 截图 / 文档」写进链路条目的「来源依据」。

| 来源 | 取数方式 | 取不到时 |
| :--- | :--- | :--- |
| App 运行态 | 用设备控制能力（computer_use 手机投屏或 Appium）在真机或模拟器上安装运行：走真实入口，逐屏记录 tab 与二级页导航路径、页面标题、控件类型与文案、默认值、必填标记、权限弹窗、软键盘遮挡、空态与错误态；要登录先确认账号与登录方式（短信验证码类需能收码的测试号），要绑定车辆或设备的先确认绑定关系；必要时按「操作与恢复」执行真实操作，取状态的真实变化 | 无设备、装不上包、要登录拿不到账号时，索取逐屏录屏或按顺序的截图序列加页面清单；**不得仅凭 App 或模块名称推断功能** |
| 小程序 | 在开发者工具或真机上打开体验版，记录页面路径、组件文案、授权弹窗、返回方式 | 无体验权限时索取截图序列与页面清单，不解析小程序码猜结构 |
| 原型·截图 | 直接读图，抄录字段名、按钮文案、占位提示、默认值、标注说明、状态枚举 | 图过小或文字不可辨时索取局部放大图或字段文字清单 |
| 原型·Figma/蓝湖 | 能打开则逐页截图后读图 | 需权限或链接失效时索取关键页面截图或导出标注 |
| 需求材料 | 解析文件（Word/PDF/Markdown/Excel）与粘贴文本，按角色、规则、状态归类 | 只有标题无正文时索取核心章节（角色、状态定义、规则约束） |

### 操作与恢复

分析链路允许在设备上做真实操作（增删改查、授权、绑定、切前后台），用来确认「状态是否真实推进」，不看提示文案；但端上很多操作不可逆，写操作必须先有还原预案，离开时设备与账号状态和进入时一致。

**先记基线，再动手。** 开始前记一份设备基线：安装包版本、登录账号、已授予的系统权限、系统语言与时间、网络与代理、已绑定的车辆或设备。结束时逐项对照这份基线，差异全部回填。

**先自建，再改动。** 验证编辑、删除、解绑时，用测试账号造临时数据（命名带固定前缀 `TMP-CL-{日期}-{序号}`，如 `TMP-CL-20261111-01`），在自建数据上闭环；不拿真实车主账号、真实车辆当试验对象。

| 操作 | 允许程度 | 恢复方式 |
| :--- | :--- | :--- |
| 浏览、切 tab、翻页、进详情与弹层 | 直接执行 | 无需恢复 |
| 安装、覆盖安装、升级 | 直接执行，先记版本与登录态 | 留着原包，测完装回原版本并重新登录 |
| 卸载重装 | 先记服务器地址、账号、绑定关系 | 装回同一版本，原账号登录并重新绑定；本地草稿、离线缓存不可恢复，属不可逆项，先确认可弃 |
| 清除应用数据、清除缓存 | 默认不做；必须做时先记配置与登录方式 | 重装或重登并重新授权；登录凭证、本地数据不保证还原，按不可逆项登记 |
| 授予、撤销系统权限（定位、相机、通知、蓝牙） | 直接执行 | 到系统设置改回原状态并复查 |
| 改系统时间、语言、网络代理、开发者选项 | 先抄原值 | 逐项改回，改完复查一次 |
| 登录、退出、切换账号 | 直接执行 | 退出并回登原账号 |
| 绑定、解绑车辆或设备 | 只在测试账号与测试设备上做 | 先记绑定关系，测完按原关系绑回 |
| 新增、编辑、删除业务数据（地址、成员、车辆别名等） | 自建数据闭环；改既有数据先抄原值 | 删掉自建数据；改过的字段改回并复查 |
| 车控类指令（开锁、鸣笛、寻车、设防、空调、车窗） | 仅测试车辆且已获授权；执行前确认车辆无人使用、处于可操作状态 | 执行后复位到原状态并确认无遗留动作；无法确认安全就不执行，标 `[未实测]` |
| 触发短信验证码、推送、支付、工单 | 不自行执行 | 列入「假设与待确认」，取得授权后再做 |

**前后各取一次基线。** 写操作前记录该对象当前状态（页面截图或字段原文，含车辆在线状态与绑定关系），操作后复查同一组状态，两次结果写进「三、环境恢复记录」。判断链路是否真实推进只看这个差异。

**收尾自检。** 结束前再查一遍：自建数据已删净、权限与系统设置已还原、绑定关系与基线一致、登录态回原账号、无未复位指令。还原不了的标 `[未实测]` 并写清缺什么条件。

## 执行

1. **归一化**：逐来源登记「来源类型 / 覆盖范围 / 粒度 / 可信度（实测 > 文档 > 推测）」，合并成原子事实：角色、业务实体、核心操作、状态、触发条件、约束规则。
2. **判信息是否足够**：缺「核心目标、参与角色、主状态定义」时先追问，一次不超过 3 个能改变结论的问题；缺细节用显式假设推进并记入「假设与待确认」。
3. **识别主干**：唯一判据是「是否有角色为完成核心目标而必须经过」。系统设置、帮助中心、消息中心默认不是主干，除非它本身就是核心目标。
4. **划分链路**：一条链路 = 一个触发条件 + 一个可独立达成的目标。除业务链外，App 端必须单独判这三条：**授权链**（安装 → 登录 → 系统权限授予 → 绑定车辆或设备）、**前后台链**（切后台、杀进程、断网后回到同一页面，状态是否保持）、**唤起链**（推送、扫码、深链、后台被杀后重新拉起落到的页面）。
5. **实测操作与还原**：按「操作与恢复」对关键节点做真实操作，把「操作前 → 操作后」的状态差异作为推进证据；端上不可逆动作（卸载重装、清数据、解绑）先确认可弃再动，每次写操作做完立即还原，不攒到最后统一清。
6. **写节点序列**：节点写「动作 + 对象」，条件分支内联标注。每个节点标承载页面——**页面名 + 导航路径**（如 `首页 › 车控 › 车辆详情`），弹层标注为某页面内弹层；路径来自实测或截图，取不到时标 `[路径待确认]`，不编造。单条链路超过 20 个节点按模块拆成多条。
7. **自检**：每个节点能回溯到来源；每条链路能独立成立；节点串首尾连续；每个节点都有页面与路径；路径不是推测；设备基线与进入时一致，恢复记录已闭环（自建数据已删净、权限与绑定已还原）。

## 输出格式

产物为单个 Markdown 文档，可直接另存为 `.md` 交付或入库。

- 文首写一级标题（产物名），下一行写 `> 来源：<上游产物或用户材料>｜生成：YYYY-MM-DD`
- 节标题统一用中文序号加固定名（一、xxx、二、xxx），名称不改，供下游按标题定位；模块级标题写「模块：<模块名>」
- 列表与表格用原生 Markdown，不用代码围栏包裹；代码围栏只包裹真正的代码
- 表格列序与列名、编号格式固定，不按现状重排
- 不输出 HTML、图片、Excel、CSV 或散装纯文本

「一、核心链路清单」与「二、假设与待确认」两个标题名固定，下游 `app-test-point-generator` 依赖它们定位内容；「三、环境恢复记录」是实测留痕，本次没做写操作时只写一行「本次未执行写操作」，设备基线照实写。

## 脚本

`scripts/` 下有可复用的辅助脚本，动手前先看有没有能省掉手工操作的：

| 脚本 | 用途 |
| :--- | :--- |
| `scripts/device_baseline.py` | 采集 / 核对设备基线（包版本、前台窗口、代理、语言、时区、已授予权限）。`snapshot` 采一次存 JSON，分析结束用 `compare` 比对、`restore --proxy` 写回代理。adb 调用统一带 `-s`。 |
| `scripts/capture_ui.py` | 抓当前屏控件树与可见文案，输出 `ui.xml` / `texts.txt` / `summary.md`，是「抄这一屏真实有什么」的标准动作。原生控件与 WebView 元素分开标注，避免误判 resource-id 前缀。 |
| `scripts/parse_links.py` | 把本步产出的链路清单解析回结构化数据（编号、名称、类型、触发条件、角色、节点串、主/分支、来源依据），节点按圈号 ①②③ 切分。写完拿它自查一遍：缺节点、缺来源依据会直接点名，避免下游誊抄漏字段。 |
| `scripts/mdutil.py` | Markdown 通用读写工具库（表格解析、章节替换、代码块提取、标题统计），其他脚本共用，也可直接 import。 |

用法示例：

```bash
python scripts/device_baseline.py snapshot --udid <udid> --package <pkg> --json base.json
python scripts/device_baseline.py compare --before base.json
python scripts/capture_ui.py --udid <udid> --out out/ui_01
python scripts/parse_links.py ../../test-design/app/01-核心链路清单.md --json links.json
```

## 禁止

- 不在没取到实际界面的情况下分析：只有 App 名称、只有应用商店介绍页、只有模块名时，先按「取数」取回内容；取不到就索取录屏或截图并停下。靠命名猜功能即为编造。
- 不编造导航路径、版本号、设备要求；未知标 `[路径待确认]`。
- 不按同类 App 的习惯补功能（「一般 App 都有消息中心」不算依据）。
- 不把页面跳转当业务链路；不把一次权限弹窗单独拆成链路（并入授权链）。
- 不在没有还原预案的情况下执行写操作：卸载重装、清除应用数据、解绑车辆这类不可逆动作，先确认可以弃数据再动手。
- 不拿真实车主账号或真实车辆做试验；绑定、解绑、改数据只在测试账号与测试设备上进行。
- 不在未获授权时下发车控指令；涉及真实车辆动作的节点标 `[需授权]` 并进「假设与待确认」。
- 不留残留：自建数据、改过的系统权限与设置、绑定关系、登录态一律还原到基线。
- 不伪造状态差异：恢复记录里的前后状态必须来自实测；推导出的状态变化标 `[推断]`，不写成结论。
- 不输出测试点、用例、优先级——那是下游 Skill 的职责。
