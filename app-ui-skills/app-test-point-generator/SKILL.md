# App 测试点生成

把链路节点和端上控件转成可验证的测试点，保证链路不断、交互不漏、系统干扰不失控。

## 输入

- 上游（优先）：`app-core-link-analyzer` 的「核心链路清单」，按链路 ID 与节点对齐，用「关键节点」串展开逐节点测试点。
- 单独调用：需求描述、页面截图、录屏、已有用例表、目标模块名称。
- 只有链路名称没有节点时，先补出节点并标 `[假设]` 再推导。
- 只有截图或录屏时，先枚举页面上的控件、弹层、权限弹窗、列表操作，再逐项展开。

## 执行

1. **建节点验证矩阵**：对每个节点问五件事——这一屏有哪些控件与输入项、前置状态是什么（登录态、权限、车辆绑定、网络）、怎么触发（点击、长按、滑动、返回）、结果落在哪一屏或哪个状态、下游依赖什么。答不出的就是待确认项。
2. **逐节点覆盖六类**，每类显式判断「有/无」，无则给理由：

   | 类型 | 覆盖内容 |
   | :--- | :--- |
   | 正向 | 端到端跑通 + 单页正确；含最短路径与含可选步骤的完整路径 |
   | 异常 | 必填缺失、格式非法、网络失败与超时、断网后恢复、服务端错误码、图片上传失败、本地缓存损坏、接口降级后的提示 |
   | 边界 | 输入长度上下限、数值精度、列表空与超长、上拉加载到底与下拉刷新、图片大小与格式、日期区间、金额阈值、超长文本换行与截断、扫码内容的边界值 |
   | 状态 | 合法迁移全枚举 + 非法迁移；端上专有：切后台再回、杀进程重进、断网重连、换账号、清缓存后同一页面状态、登录态过期后的跳转 |
   | 交互 | 权限弹窗（定位、蓝牙、相机、通知、存储）、软键盘遮挡与收起、返回键与侧滑返回、长按与双击、下拉刷新与上拉加载、Toast/Snackbar 文案与消失时机、加载态与空态、横竖屏、深色模式、推送点击落地页 |
   | 权限与兼容 | 拒绝权限后的降级路径与二次开启、账号角色可见性、越权访问入口是否存在、机型 × 系统版本 × 分辨率 × 厂商定制 ROM 的表现差异、弱网与飞行模式、低电量模式、后台被系统回收 |

3. **控件必查边界**：每个输入项都要有独立边界测试点（空、长度上下限、格式非法、特殊字符），不允许用一条「必填校验」代表整张表单；开关、滑杆、选择器要单列默认值与可选集合。
4. **链路级补充**：授权链一次（含拒绝、去设置页开启、仅本次允许）、前后台链一次（切后台、杀进程、断网重连）、唤起链一次（推送、扫码、深链落地页）；升级安装（覆盖安装后登录态与数据是否保留）一次。
5. **去重与追溯**：每个测试点挂到链路 ID 与节点；挂不上的要么补节点要么删。同一规则的多控件表现合并为一条，用「分别验证」表述。
6. **定优先级**：P1 主链路正向、资金与数据一致性、授权链阻断类；P2 一般异常与边界；P3 兼容矩阵与低频交互组合。

## 输出格式

产物为单个 Markdown 文档，可直接另存为 `.md` 交付或入库。

- 文首写一级标题（产物名），下一行写 `> 来源：<上游产物或用户材料>｜生成：YYYY-MM-DD`
- 节标题统一用中文序号加固定名（一、xxx、二、xxx），名称不改，供下游按标题定位；模块级标题写「模块：<模块名>」
- 列表与表格用原生 Markdown，不用代码围栏包裹；代码围栏只包裹真正的代码
- 表格列序与列名、编号格式固定，不按现状重排
- 不输出 HTML、图片、Excel、CSV 或散装纯文本

### 一、测试点清单

#### 模块：车控

- 链路：CL-01 车控设防（节点：①首页 › 车控 → ②车辆详情 → ③设防确认弹层 → ④指令下发 → ⑤结果页）
  - TP-001 [正向] 车辆在线时点击设防并确认，结果页显示设防成功且车辆状态变为已设防
  - TP-002 [异常] 断网状态下点击设防，停在确认弹层并提示网络异常，不显示成功
  - TP-003 [边界] 备注输入框长度为上限与上限+1 时的截断与提示表现
  - TP-004 [状态] 设防成功后切后台再回到结果页，状态展示保持一致，不回到未设防
  - TP-005 [交互] 蓝牙权限被拒绝时点击设防，出现授权引导而非直接失败
  - TP-006 [交互] 软键盘弹出时底部按钮是否被遮挡、收起后是否恢复可点
  - TP-007 [兼容] 同一操作在低端机型（小屏、低内存）与旗舰机上的布局与响应差异

## 脚本

`scripts/` 下的辅助脚本，用于解析上游链路清单与自查覆盖情况：

| 脚本 | 用途 |
| :--- | :--- |
| `scripts/parse_links.py` | 把上游 01 文件的链路小节解析成结构化 JSON（编号、名称、类型、触发条件、角色、节点串、主/分支、来源依据），节点按圈号 ①②③ 切分。避免人工誊抄漏字段。 |
| `scripts/coverage_check.py` | 自查测试点清单：每条 TP 是否挂了链路 ID 与节点、是否带六类标签；`--table` 直接生成「覆盖自查」表骨架。标签体系不同时用 `--categories` 指定。 |
| `scripts/mdutil.py` | Markdown 通用读写工具库（表格解析、章节替换、代码块提取、标题统计）。 |

用法示例：

```bash
python scripts/parse_links.py ../../test-design/app/01-核心链路清单.md --json links.json
python scripts/coverage_check.py ../../test-design/app/02-测试点清单.md --table
```

## 禁止

- 不写执行步骤与预期结果，测试点只描述「验证什么」，落到操作是 `app-test-case-writer` 的职责。
- 不编造链路之外的业务规则；规则不确定时进「待确认」而不是按常识补。
- 不用多条同质测试点充数，也不把「必填、长度、格式」压成一条。
- 不把兼容性含糊成一句「多机型适配」，要列出具体的机型、系统版本、分辨率组合。
- 不按「同类 App 都有这个交互」补测试点；没看到的控件不列。
