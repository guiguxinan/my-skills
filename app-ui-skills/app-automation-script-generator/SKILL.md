# App 自动化脚本生成

端上脚本的成败在设备准备与控件识别，不在断言写法。这两件先解决，再谈代码。

## 输入

- 上游（优先）：`app-automation-feasibility-analyzer` 的「可自动化用例清单」，含用例编号、类型、改造前置。
- 单独调用：App 用例表 + 技术栈 + 安装包 + 控件树导出或页面截图 + 测试账号。
- **定栈顺序（必须先定，再动笔）**：① 用户指定；② 目标仓库已有框架——看 `requirements.txt` / `package.json` / `pytest.ini` / `conftest.py` / `AGENT.md` / `README.md`，沿用它的目录、命名、fixture 与报告工具；③ 都没有再追问并给推荐默认。文档与代码冲突时以代码为准，差异写进「待补清单」。
- **取真实控件**：依次取——仓库自带的控件抓取工具或 Appium Inspector 导出 → 用户给的控件树 XML / 页面源码 → 占位 `[待补:所需信息]` 且该用例标记跳过。禁止按同级页面或同类 App 推断 locator。
- 硬约束：不编造控件 id、按钮文案、包名与 Activity；不写只打印不断言的伪测试。

## 执行

1. **骨架**：能沿用目标仓库就不新建；新建时按「一个业务模块一处页面对象 + 一处数据 + 一处用例」，三者模块名对齐。
2. **设备与环境**：capabilities 外置到矩阵文件（设备编号、platformName、系统版本、udid、包名、启动页），不写死在用例里；启动策略明确 `noReset` / `fullReset` / 清数据，用例间保证隔离；安装与卸载、测试包版本固定可追溯。
3. **定位器优先级**：accessibility id / testID → 资源 id 或控件 id → 类名 + 稳定属性组合 → 可见文案 → 层级路径（末选，命中处标 `[脆弱定位]` 并进待补清单补标识）。禁止下标定位与绝对坐标；Flutter、React Native 用其原生 key 或语义标识；内嵌 H5 先切到 webview 上下文再定位，切回后重新建立句柄。
4. **等待**：只用显式等待（元素可见、可点、文案出现、页面标题变化），超时分类配置（启动、页面切换、列表加载、弹层各一套）；禁止 `sleep`。断言前先确认进入稳定态——同一状态连续两次读到一致再判。
5. **交互**：点击前先收起软键盘并确认元素未被遮挡；长列表先滚动到元素再点，不用固定次数滑动；长按、双击、拖拽用框架提供的能力，滑动用比例而非像素；返回键与侧滑返回分开处理，iOS 无返回键时不得复用 Android 逻辑。
6. **系统干扰**：权限弹窗按平台分别预置（Android 可预授权，iOS 需重置授权状态）或写应答器；通知、来电、锁屏、切前台后台、横竖屏、深色模式、系统语言与时区都作为可配置项，不假设为默认状态。
7. **数据与清理**：账号、绑定的车辆或设备、订单等取值外置到数据文件或环境变量，不硬编码；唯一值用生成规则构造；破坏性用例打标记并在用例内恢复（解绑、复位、删除本用例新增的数据），只回收本用例期间新增的差集。
8. **多机型矩阵**：按设备分片执行，用例与设备组合由矩阵决定；截图、录屏、日志按设备与会话归档，失败产物能一眼看出是哪台设备。
9. **标注与报告**：按仓库既有报告工具分类——模块级 feature、功能分组的 story、带用例编号前缀的 title、由优先级换算的 severity；打齐冒烟、回归、慢速、兼容、破坏性标记，新标记同步注册。
10. **自检**：每条脚本能追溯到原用例编号；每例有断言且只判界面层事实；全文无 `sleep`、无编造控件、无下标或坐标定位、无硬编码凭据；能跑一遍，或说明为何未跑（缺设备、缺包、缺账号、缺控件树）。

## 分栈落地参考

只有定了栈才看对应一行；表里没有的栈按该栈官方骨架写，只保留上面的通用原则。

| 场景 | 典型骨架 | 该栈的落地点 |
| :--- | :--- | :--- |
| Android·Appium + UiAutomator2 | `pages/<module>/`、`data/`、`tests/`、`capabilities/` | capabilities 外置矩阵；权限可预授权；启动策略与清数据写在 fixture |
| iOS·Appium + XCUITest | 同上 | 需 WebDriverAgent 签名可用；授权状态需重置；无返回键，用导航栏按钮或侧滑 |
| 小程序·miniprogram-automator | 按页面路径组织页面对象 | 依赖开发者工具或真机自动化通道，进入页需指定路径与参数 |
| 混合 App·内嵌 H5 | 页面对象按 context 分层 | 进 webview 前切上下文、退出后切回并重建句柄；H5 内部定位沿用 Web 规则 |
| Flutter / React Native | 页面对象按 widget 树组织 | 用 ValueKey / testID 或语义标识定位，必要时开启语义树 |
| 原生单栈（Espresso / XCUITest） | 按 gradle 或 xcodeproj 既有结构 | 与 Appium 混用时注意进程隔离与清理 |

## 输出格式

产物为单个 Markdown 文档，可直接另存为 `.md` 交付或入库。

- 文首写一级标题（产物名），下一行写 `> 来源：<上游产物或用户材料>｜生成：YYYY-MM-DD`
- 节标题统一用中文序号加固定名（一、xxx、二、xxx），名称不改，供下游按标题定位；模块级标题写「模块：<模块名>」
- 列表与表格用原生 Markdown，不用代码围栏包裹；代码围栏只包裹真正的代码
- 表格列序与列名、编号格式固定，不按现状重排
- 不输出 HTML、图片、Excel、CSV 或散装纯文本

### 一、设计简述

选了哪套栈与依据、设备与 capabilities 策略、目录与分层、定位与等待策略、数据与清理策略、执行顺序与分片方式。

### 二、用例映射表

`原用例编号 → 文件 → 页面对象方法 → 设备矩阵 → 状态（可运行 / skip 待补）`。

### 三、代码

按文件分块（页面对象 → 数据与 capabilities → 用例），只给新增与改动部分；注释写业务意图与易踩点（如「此页点击前必须收起键盘」「设防结果需等状态标签稳定两次」），不解释语法。

### 四、运行说明

设备与依赖准备（Appium server、驱动、签名、adb 或 xcrun）、安装包与版本、环境变量与账号配置、执行命令（全量 / 单模块 / 单用例 / 按设备 / 按标记）、报告命令、失败产物位置、重跑与重置方式。

### 五、待补清单

缺的控件标识、需要补的测试账号与测试车辆、设备池缺口、需要 mock 的系统能力，逐条说明需要谁提供什么。

## 脚本

`scripts/` 下的辅助脚本，用于生成映射表与自检脚本文档：

| 脚本 | 用途 |
| :--- | :--- |
| `scripts/gen_mapping.py` | 从上游可自动化清单生成「二、用例映射表」整表（按 JSON 配置分派文件 / 页面对象方法 / 设备矩阵 / 状态），替换目标文档里那张表的数据行。避免手写 200 行时漏号、重号、状态写错。列名与模块前缀规则随项目不同，在配置里用 `columns` / `module_regex` 指定。 |
| `scripts/check_script_doc.py` | 自检本文档：无 `sleep`、无裸 `assert`、无下标 / 坐标定位、无硬编码凭据；每个测试函数都有断言、都能追溯到用例编号；带 `--repo` 时还会扫描目标仓库，校验代码里引用的页面对象方法 / 属性真实存在。App 栈用 `--profile app`（另可用 `web` / `api` 档位）。 |
| `scripts/mdutil.py` | Markdown 通用读写工具库（表格解析、章节替换、代码块提取、标题统计）。 |

用法示例：

```bash
python scripts/gen_mapping.py --from ../../test-design/app/04-自动化选型.md         --to ../../test-design/app/05-自动化脚本.md --config mapping.json
python scripts/check_script_doc.py ../../test-design/app/05-自动化脚本.md --repo <仓库根>
```

## 禁止

- 不编造控件 id、文案、包名、启动页；缺就占位并标记跳过。
- 不用 `sleep`、不用固定坐标、不用下标定位。
- 不把设备差异写进用例逻辑；差异放 capabilities 与矩阵。
- 不假设权限已授予、不假设无通知打扰、不假设应用在前台。
- 不在页面对象里写断言与业务判断；不在用例层重复拼装定位细节。
- 不硬编码真实账号、手机号、密钥与 VIN，不把它们写进日志。
- 不用整句文案断言提示，不写死列表总条数。
- 改数据的用例不回收数据，也不用 id 区间批量删除。
- 不改写用例的业务预期以让脚本通过；预期与实现冲突时保留原预期并报告。
