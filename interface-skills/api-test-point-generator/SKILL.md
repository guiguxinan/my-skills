# 接口测试点生成

把接口和链路转成可验证的测试点，保证链路不断、字段不漏、契约不破。

## 输入

- 上游（优先）：`api-core-link-analyzer` 的「接口链路清单」，按链路 ID 与节点对齐，用「关键节点」串展开逐接口测试点。
- 单独调用：接口文档（Swagger/OpenAPI、Apifox、Collection）、抓包样例、需求说明、已有用例表。
- 只有接口名没有字段定义时，先索取一条真实请求/响应，再推导；不要按字段名猜类型与约束。
- 只有需求没有接口定义时，先按业务补出接口粒度并标 `[假设]`。

## 执行

1. **建接口验证矩阵**：对每个接口问五件事——入参有哪些（含必填与类型）、前置状态是什么、鉴权与角色要求、返回什么（含错误码）、有什么副作用（写表、发消息、改缓存）。答不出的就是待确认项。
2. **逐接口覆盖六类**，每类显式判断「有/无」，无则给理由：

   | 类型 | 覆盖内容 |
   | :--- | :--- |
   | 正向 | 端到端链路跑通 + 单接口正确返回；含最短路径与含可选字段的完整路径 |
   | 参数 | 必填缺失、类型错误、长度上下限与上限+1、格式非法、枚举越界、空值语义（`null` / 缺省 / 空串 三者区分）、多余字段、嵌套结构畸形、超长报文 |
   | 状态与规则 | 合法状态迁移全枚举 + 非法迁移（跳过中间态、逆向回退）、业务前置不满足（未支付就发货、库存不足）、唯一性冲突 |
   | 幂等与并发 | 重复提交、重放同一请求、带不同幂等键重复提交、并发同单、请求乱序、版本号或乐观锁冲突 |
   | 鉴权与权限 | 无 token、token 过期、token 篡改、越权访问他人资源、角色边界、租户或组织隔离、越权字段（传入无权操作的 ID） |
   | 契约与容错 | 字段必返与类型、错误码与提示语、分页与排序语义、下游超时/降级/重试、依赖服务不可用、限流与重复调用 |

3. **逐字段必查边界**：每个入参字段都要有独立边界测试点（必填、类型、长度、枚举、特殊字符、空值语义），不允许用一条「必填校验」代表整个接口。
4. **链路级补充**：端到端正向一次；断链（前置接口失败、中间接口失败后是否回滚、重试是否重复落库）各一次；依赖失效（token 过期后继续调用、上游数据被删后下游重试）各一次。
5. **去重与追溯**：每个测试点挂到链路 ID 与接口节点；挂不上的要么补节点要么删。同一规则的多字段表现合并为一条，用「分别验证」表述。
6. **定优先级**：P1 主链路正向、资金与数据一致性、鉴权绕过，P2 一般参数与状态异常，P3 边界组合与低频容错。

## 输出格式

产物为单个 Markdown 文档，可直接另存为 `.md` 交付或入库。

- 文首写一级标题（产物名），下一行写 `> 来源：<上游产物或用户材料>｜生成：YYYY-MM-DD`
- 节标题统一用中文序号加固定名（一、xxx、二、xxx），名称不改，供下游按标题定位；模块级标题写「模块：<模块名>」
- 列表与表格用原生 Markdown，不用代码围栏包裹；代码围栏只包裹真正的代码
- 表格列序与列名、编号格式固定，不按现状重排
- 不输出 HTML、图片、Excel、CSV 或散装纯文本

### 一、测试点清单

#### 模块：订单

- 链路：CL-01 下单主链路（节点：①登录 → ②查购物车 → ③创建订单 → ④预支付 → ⑤轮询状态）
  - TP-001 [正向] 带有效 token 创建订单，返回 200 且 data.orderId 非空，订单状态为待支付
  - TP-002 [参数] 缺少 items 字段提交，返回业务码「参数缺失」且不落库
  - TP-003 [参数] 收货人姓名长度为上限（20）与上限+1（21）时分别的返回表现
  - TP-004 [状态] 订单处于「已支付」时再次调用创建接口同一 requestId，返回幂等结果不生成新单
  - TP-005 [幂等并发] 同一 requestId 并发 10 次提交，最终仅落库 1 条订单
  - TP-006 [鉴权] token 过期后调用，返回 401 且不泄露业务数据
  - TP-007 [契约] 非分页接口的返回结构缺字段或类型变更，契约校验应失败

## 禁止

- 不写执行步骤与预期结果，测试点只描述「验证什么」，落到请求是 `api-test-case-writer` 的职责。
- 不编造字段名、错误码、业务码；不确定时进「待确认」，不按命名习惯补。
- 不用多条同质测试点充数，也不把「必填、类型、长度」压成一条。
- 不把 HTTP 200 等同于业务成功；测试点里要区分传输层与业务层结论。
- 不给没有链路归属的散点测试点。
