# 接口自动化适用性分析

接口用例的「能跑」和「值得跑」是两件事，这里给结论与依据。

## 输入

- 上游（优先）：`api-test-case-writer` 的用例表，按用例编号对齐。
- 单独调用：任意来源的用例表（Excel/CSV/Markdown）、接口清单、场景列表。
- 先解析列结构：识别 编号/标题/优先级/前置/请求/预期（外部表格列序可能不同，按列名映射而非按位置猜）。缺请求列时只能按标题与预期推断可断言性，结论标 `[信息不足]` 并降低置信度。
- 额外增益输入（有则用）：是否有 OpenAPI/契约文件、能否用造数接口构造数据、测试环境是否独立可重置、是否已有鉴权封装与 mock 能力。

## 执行

1. **五维打分**，每维 1–5，写分值不写形容词：

   | 维度 | 5 分情形 | 1 分情形 |
   | :--- | :--- | :--- |
   | 调用频次 | 每次发版必回归、上线后需巡检 | 一次性数据修复验证 |
   | 契约稳定性 | 有正式契约且半年未变 | 接口随需求周周改、无文档 |
   | 数据可构造 | 造数接口一键造、可重置 | 依赖生产真实数据、影响共享环境 |
   | 断言可判定 | 状态码、业务码、关键字段、副作用都明确 | 只能人工看返回内容判断 |
   | 单次执行成本 | 手工需逐个拼报文、耗时 10 分钟以上 | 手工 Postman 点一下即可 |

2. **按总分定池**：≥18 可自动化；12–17 有条件自动化（需先补契约、造数或 mock）；<12 手工。
3. **先过一票否决**，命中即入手工池，不论分数多高：依赖真实第三方且无法 mock（真实支付、短信、外部实名）；需要人工审批或线下签核才能推进的业务；无契约的私有协议、强加密且无测试夹具；依赖特定并发时序或硬件状态的异常；一次性数据修复与线上问题复现。
4. **定类型**：契约与字段结构可静态校验的判「契约」；纯业务行为验证判「接口」；需要接口造数 + 数据层校验、或接口操作后再查库核对后果的判「混合」。
5. **给改造前置**：把「有条件」转成「可自动化」的最小动作，写成可指派的任务——补 OpenAPI 契约、搭 mock 或 stub、写造数与清数脚本、封装鉴权与 token 复用、准备参数化数据集。
6. **排批次**：P1 且高频的先做，作为第一批；第一批控制在 10–20 条以便快速验证框架可用，其余按模块成批；串行依赖强的链路整条成批，不要拆散。
7. **给收益口径**：按「用例数 × 单次执行时长 × 年回归次数」估算节省工时，写清假设值。

## 输出格式

产物为单个 Markdown 文档，可直接另存为 `.md` 交付或入库。

- 文首写一级标题（产物名），下一行写 `> 来源：<上游产物或用户材料>｜生成：YYYY-MM-DD`
- 节标题统一用中文序号加固定名（一、xxx、二、xxx），名称不改，供下游按标题定位；模块级标题写「模块：<模块名>」
- 列表与表格用原生 Markdown，不用代码围栏包裹；代码围栏只包裹真正的代码
- 表格列序与列名、编号格式固定，不按现状重排
- 不输出 HTML、图片、Excel、CSV 或散装纯文本

### 四、假设与待确认

## 脚本

`scripts/` 下的辅助脚本，用于打分核算与分池校验：

| 脚本 | 用途 |
| :--- | :--- |
| `scripts/score_cases.py` | 五维打分与分池核算。`--template` 生成打分 CSV 模板（按上游用例编号预填），填完用 `--csv` 算汇总表草稿；对本步产物用 `--verify` 核对「可自动化 / 有条件 / 手工」三张表与「三、汇总」的数字是否自洽、分池区间有无越界。 |
| `scripts/mdutil.py` | Markdown 通用读写工具库（表格解析、章节替换、代码块提取、标题统计）。 |

用法示例：

```bash
python scripts/score_cases.py ../../test-design/api/03-测试用例.md --template scores.csv
python scripts/score_cases.py ../../test-design/api/04-自动化选型.md --verify
```

## 禁止

- 不给逐条打分的空转结论：每条必须有总分、判定依据、可执行的下一步。
- 不以「能发出请求、返回 200」作为可自动化理由；响应正确性无法判定时按低分处理。
- 不跳过一票否决直接看分数。
- 不把用例改写成新用例，也不生成脚本——编码是 `api-automation-script-generator` 的职责。
- 不虚构调用频次、契约稳定性等输入中不存在的事实，缺失时标 `[待确认]` 并在汇总里注明假设。
