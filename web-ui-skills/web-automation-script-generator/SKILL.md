# Web 自动化脚本生成

产出能跑、失败能定位的脚本。定位器拿不到先探测、探测不到就占位，不猜。

## 输入

- 上游（优先）：`web-automation-feasibility-analyzer` 的「可自动化用例清单」，含用例编号、类型、改造前置。
- 单独调用：UI 用例表 + 技术栈 + 页面 DOM、元素截图或真实定位标识。
- **定栈顺序（必须先定，再动笔）**：① 用户指定；② 目标仓库已有框架——看 `package.json` / `playwright.config.*` / `pytest.ini` / `conftest.py` / `requirements.txt` / `AGENT.md` / `README.md`，沿用它的目录、命名、fixture、断言与报告工具，不另起一套；③ 都没有再追问，并给一个推荐默认。文档与代码冲突时以代码为准，差异写进「待补清单」。选栈依据写进「设计简述」首行。
- **取真实定位**：依次取——仓库自带的抓取/探测工具（如导出候选定位器的脚本）→ 用户给的截图、DOM、页面源码 → 占位 `[待补:所需信息]` 且该用例标记跳过。禁止按页面名称或同类页面推断选择器。
- 硬约束：不编造选择器、字段名、提示文案；不写只打印不断言的伪测试。

## 执行

1. **骨架**：能沿用目标仓库就不新建；新建时保证「一个业务模块一处」——页面对象、数据、用例三处用同一模块名对齐，失败产物按模块归档。
2. **分层职责**：页面对象只放定位器与页面动作，不写断言、日志、测试数据；断言与日志写用例层；前置数据与清理放 fixture；超时与路径集中配置，不硬编码在方法里。
3. **定位器优先级**：语义属性（`name` / `id` / `role` / `label` / 测试专用属性）→ 稳定 class 或按表单标签锚定 → 可见文案 → 结构选择器（末选，命中处标 `[脆弱定位]` 并进待补清单换稳定标识）。禁止行内下标（`nth-child`、行内图标序号），禁止依赖框架动态生成 id 的绝对路径。
4. **等待**：只用框架的显式等待，超时取配置，禁止 `sleep` 与固定延时。轮询条件里不要用会被页面导航阻塞的元素查找，改用轻量判定；同一状态要求「连续两次读到一致」再放行，避免把「还没数据」当成「已就绪」。
5. **时序**：先等待再断言。异步跳转、瞬态提示（可能几秒后消失且初始文本为空）、异步回填（先渲染编码再换文案）、列表先渲染后刷新的抖动，都走页面对象里的 `wait_for_xxx`，不在断言后补等待。
6. **弹层**：同类弹层常同时存在多个实例（含隐藏的），选择器先过滤出「可见且标题匹配」的那一个；开关状态按实测特征判定（有的只靠 `display`，有的不支持 ESC 关闭），不按直觉。
7. **断言**：每条用例至少一个业务级断言——最终状态、列表条数、字段值、跳转路径。文案类用关键字集合而非整句；条数类不写死绝对值（数据会变），用正则、`>=` 或参考值。只断言界面层可判定的事实，协议层与落库留给接口用例。失败信息要能看出期望值与实际值。
8. **数据**：取值外置到数据文件、配置或环境变量，不硬编码账号与密钥，不写进日志（需体现账号时脱敏）；参数化把取值外置、用场景名当用例 id；每条用例可单独运行、可乱序运行。
9. **破坏性用例**：删除、审核、导入这类改数据的用例打标记，并在用例内做数据准备与回收。逻辑删除按业务标记字段恢复；只能自建的数据自建自删；异步落库的等记录真正生成后再登记清理 id，且只删「本用例期间新增」的差集，不按 id 区间批量删。环境数据被消耗完时跳过用例，不判失败。
10. **标注与报告**：按仓库既有报告工具分类——模块级 feature、功能分组的 story、带用例编号前缀的 title、由用例优先级换算的 severity；打齐冒烟/回归/慢速/安全/破坏性标记，新标记同步注册。关键步骤包成步骤块，让它同时进日志与报告。
11. **自检**：每条脚本能追溯到原用例编号；每例有断言；全文无 `sleep`、无编造定位器、无下标定位、无硬编码凭据；同一模块用例归在一处；能跑一遍，或说明为何未跑（缺环境、缺账号、缺定位器）。改了公共代码要跑一轮验证。

## 分栈落地参考

只有定了栈才看对应一行；表里没有的栈按该栈官方骨架写，只保留上面的通用原则。

| 场景 | 典型骨架 | 该栈的落地点 |
| :--- | :--- | :--- |
| Web·Python + Selenium + Pytest + Allure | `pages/<module>/`、`data/<module>/`、`testcases/test_<module>/`、`common/`、`core/`、`utils/` | 页面对象继承唯一基类、定位器写类级常量元组；显式等待取配置；断言类提供单点与软断言；步骤块统一封装；截图与录屏由框架钩子产出，用例里不手写截图 |
| Web·Playwright + TS | `tests/`、`pages/`、`fixtures/`、`data/` | 定位器走 role / label / 测试专用属性；用内建轮询式断言；trace 与截图由配置产出 |
| Web·Cypress / Jest | 按该栈官方骨架 | 交互式重试由框架负责；断言仍按「业务级 + 不写死条数」 |

## 输出格式

产物为单个 Markdown 文档，可直接另存为 `.md` 交付或入库。

- 文首写一级标题（产物名），下一行写 `> 来源：<上游产物或用户材料>｜生成：YYYY-MM-DD`
- 节标题统一用中文序号加固定名（一、xxx、二、xxx），名称不改，供下游按标题定位；模块级标题写「模块：<模块名>」
- 列表与表格用原生 Markdown，不用代码围栏包裹；代码围栏只包裹真正的代码
- 表格列序与列名、编号格式固定，不按现状重排
- 不输出 HTML、图片、Excel、CSV 或散装纯文本


### 一、设计简述

选了哪套栈与依据、目录与分层、定位与等待策略、数据与清理策略、运行顺序。

### 二、用例映射表

`原用例编号 → 文件 → 类或方法 → 状态（可运行 / skip 待补）`。

### 三、代码

按文件分块（页面对象 → 数据 → 用例），只给新增与改动部分；注释写业务意图与易踩点，不解释语法。

### 四、运行说明

依赖安装、环境变量与账号配置、执行命令（全量 / 单模块 / 单用例 / 按标记）、报告命令、失败产物位置、重跑方式。

### 五、待补清单

缺的定位器、需要补的测试账号、外部依赖，逐条说明需要谁提供什么。

## 禁止

- 不编造选择器、字段名、提示文案；缺就占位并标记跳过。
- 不用 `sleep`、不用固定延时、不用行内下标定位。
- 不在页面对象里写断言、日志、测试数据；不在用例层重写定位器细节。
- 不硬编码真实账号、手机号、密钥，不把它们写进日志。
- 不用整句文案断言页面提示；不写死列表总条数。
- 不在 UI 用例里断言接口返回码与落库值；跨层验证另起接口用例。
- 改数据的用例不回收数据，也不用 id 区间批量删除。
- 不改写用例的业务预期以让脚本通过；预期与实现冲突时保留原预期并报告。
