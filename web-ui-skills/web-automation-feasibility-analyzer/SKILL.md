# Web 自动化适用性分析

给出可执行的分池结论和依据，而不是「这些页面都能点通，都可以自动化」。

## 输入

- 上游（优先）：`web-test-case-writer` 的用例表，按用例编号对齐。
- 单独调用：任意来源的用例表（Excel/CSV/Markdown）、用例列表、页面场景清单。
- 先解析列结构：识别 编号/标题/优先级/前置/步骤/预期（外部表格列序可能不同，按列名映射而非按位置猜）。缺步骤列时只能按标题与预期推断可断言性，结论标 `[信息不足]` 并降低置信度。
- 额外增益输入（有则用）：是否有稳定的自动化定位标识（testid、accessibility id、控件路径、业务主键等）、是否存在可用的数据构造接口、页面是否频繁改版、CI 环境是否具备。

## 执行

1. **五维打分**，每维 1–5，写分值不写形容词：

   | 维度 | 5 分情形 | 1 分情形 |
   | :--- | :--- | :--- |
   | 执行频次 | 每次发版必回归 | 一次性活动验证 |
   | 稳定性 | 界面结构与交互半年未变 | 页面每周改版 |
   | 数据可构造 | 接口一键造数与清数 | 依赖生产真实数据、只能手工摆数据 |
   | 断言可判定 | 有明确状态、字段、文案 | 只能人工看观感 |
   | 单次执行成本 | 手工需 10 分钟以上 | 手工点两下即完成 |

2. **按总分定池**：≥18 可自动化；12–17 有条件自动化（需先补定位标识、测试数据或造数接口）；<12 手工。
3. **先过一票否决**，命中即入手工池，不论分数多高：依赖人工视觉/听觉/主观判断（配色、动效、语气、拟真度）；一次性活动或时效性验证；破坏性且不可回滚的数据操作；强依赖真实第三方与人工审批；极端难构造的异常（特定并发窗口、硬件故障）。
4. **定类型**：只有在界面上才看得见、且页面状态足以证明的判纯 UI（展示、交互态、权限可见性、多端一致性）；操作走界面而断言落在接口或数据的判混合。别把「必须查库才能确认」的用例判成纯 UI。
5. **给改造前置**：把「有条件」转成「可自动化」的最小动作，写成可指派的任务——补稳定定位标识、申请固定测试账号、加造数与清库脚本、mock 外部依赖、把页面写操作改成接口前置。
6. **排批次**：P1 且高频的先做，作为第一批；第一批控制在 10–20 条以便快速验证框架可用，其余按模块成批。
7. **给收益口径**：按「用例数 × 单次执行时长 × 年回归次数」估算节省工时，写清假设值，不写「大幅提升效率」。

## 输出格式

产物为单个 Markdown 文档，可直接另存为 `.md` 交付或入库。

- 文首写一级标题（产物名），下一行写 `> 来源：<上游产物或用户材料>｜生成：YYYY-MM-DD`
- 节标题统一用中文序号加固定名（一、xxx、二、xxx），名称不改，供下游按标题定位；模块级标题写「模块：<模块名>」
- 列表与表格用原生 Markdown，不用代码围栏包裹；代码围栏只包裹真正的代码
- 表格列序与列名、编号格式固定，不按现状重排
- 不输出 HTML、图片、Excel、CSV 或散装纯文本

### 四、假设与待确认

## 禁止

- 不给逐条打分的空转结论：每条必须有总分、判定依据、可执行的下一步。
- 不以「UI 能点通」作为可自动化理由；能点通说明可行，不等于值得做。
- 不跳过一票否决直接看分数。
- 不把用例改写成新用例，也不生成脚本——编码是 `web-automation-script-generator` 的职责。
- 不虚构执行频次、改版频率等输入中不存在的事实，缺失时标 `[待确认]` 并在汇总里注明假设。
