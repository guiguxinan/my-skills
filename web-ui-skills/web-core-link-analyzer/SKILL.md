# Web 核心链路分析

把页面形态、原型和需求归一成同一份上下文，输出下游可直接消费的链路清单，并让每个节点落到具体页面。

## 输入

| 来源 | 说明 | 用途 |
| :--- | :--- | :--- |
| 网址（Web） | 任意模块页、详情页、弹窗页，不要求全站首页 | 取实际形态：入口菜单、路由、页面字段、按钮文案、默认值与必填标记 |
| 原型图 | 截图、Figma 链接、原型文字描述 | 取设计意图、字段约束、交互态 |
| 需求材料 | PRD、需求说明、业务说明、状态机定义 | 取业务口径：角色、规则、状态定义 |

### 取数

先取到内容再谈分析。按下表取数，并把「实测 / 截图 / 文档」写进链路条目的「来源依据」。

| 来源 | 取数方式 | 取不到时 |
| :--- | :--- | :--- |
| 网址（Web） | 用当前环境可用的网页读取能力打开该 URL——浏览器控制（Browser Use / computer_use / Chrome DevTools MCP / Playwright MCP）或网页抓取（WebFetch，动态页需改用浏览器）——进入具体模块页：点菜单、切 tab、滚动加载、开列表与弹窗，逐项记录真实菜单路径、路由、字段名、按钮文案、默认值、必填标记、空态与错误态 | 无浏览器能力、需登录拿不到账号、页面打不开时，索取页面截图或菜单结构导出；**不得仅凭 URL 字符串推断功能** |
| 原型图·截图 | 直接读图，抄录字段名、按钮文案、占位提示、默认值、标注说明、状态枚举 | 图过小或文字不可辨时，索取局部放大图或字段文字清单 |
| 原型图·Figma/在线稿链接 | 能打开则逐页截图后读图 | 需权限或链接失效时索取关键页面截图或导出标注，不解析链接猜结构 |
| 需求材料 | 解析文件（Word/PDF/Markdown/Excel）与粘贴文本，按角色、规则、状态归类 | 只有标题无正文时，索取全文或核心章节 |

## 执行

1. **归一化**：逐来源登记「来源类型 / 覆盖范围 / 粒度 / 可信度（实测 > 文档 > 推测）」，合并成原子事实：角色、业务实体、核心操作、状态、触发条件、约束规则。
2. **判信息是否足够**：缺「核心目标、参与角色、主状态定义」时先追问，一次只问能改变结论的问题（不超过 3 个）；缺细节时用显式假设推进并记入「假设与待确认」。
3. **识别主干**：唯一判据是「是否有角色为完成核心目标而必须经过」。筛选、导出、打印、消息提醒、帮助文档默认不是主干，除非它本身就是核心目标。
4. **划分链路**：一条链路 = 一个触发条件 + 一个可独立达成的目标。按业务模块或用户旅程切分，标主链路/分支链路，并写明链路间的依赖（如支付链路依赖登录态）。
5. **写节点序列**：节点写「动作 + 对象」，条件分支在主线节点后用 `（条件：分支动作）` 内联标注，不为分支单独拆链路。**同时给每个节点标出承载页面**（页面名 + 路由），路由来自实测或文档；弹窗类节点标注其为某页面的弹层。单条链路节点超过 20 个时按模块拆成多条。
6. **自检**：每个节点能回溯到某个来源；每条链路能独立成立；节点串首尾连续、无断点；每个节点都有承载页面；页面名与路由来自实测或文档，不是推测。

## 输出格式

产物为单个 Markdown 文档，可直接另存为 `.md` 交付或入库。

- 文首写一级标题（产物名），下一行写 `> 来源：<上游产物或用户材料>｜生成：YYYY-MM-DD`
- 节标题统一用中文序号加固定名（一、xxx、二、xxx），名称不改，供下游按标题定位；模块级标题写「模块：<模块名>」
- 列表与表格用原生 Markdown，不用代码围栏包裹；代码围栏只包裹真正的代码
- 表格列序与列名、编号格式固定，不按现状重排
- 不输出 HTML、图片、Excel、CSV 或散装纯文本

## 禁止

- 不在没取到实际内容的情况下分析：只有 URL 字符串、只有链接或只有文档标题时，先按「取数」取回内容；取不到就索取材料并停下。靠命名猜功能即为编造（把 `/order/list` 推成「有筛选、导出、分页」就是这种错）。
- 不补写输入中不存在的页面或节点；无法确认的标 `[待确认]` 并进「假设与待确认」。
- 不把页面跳转当业务链路：跳转不等于状态推进，判断依据是数据或订单状态是否实质变化。
- 不给节点编造路由；路由未知时写页面名并标 `[路由待确认]`。
- 不输出测试点、用例、优先级——那是下游 Skill 的职责。
