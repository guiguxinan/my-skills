# Web 测试用例编写

产出的每条用例，必须是另一个测试人员不看需求也能在页面上照做的操作序列。

## 输入

- 上游（优先）：`web-test-point-generator` 的「测试点清单」，按 TP 编号对齐，一个测试点可展开为多条用例。
- 单独调用：测试点、功能点描述、原型、已有用例表（Excel、CSV、Markdown 均可；先解析列结构再映射，不默认列名）。
- 必填上下文：被测入口（URL 或菜单路径）、测试账号与测试数据。缺失时列出「数据准备清单」并标 `[待准备]`，不虚构账号或取值。
- 已有用例表作为输入时：保留原文编号，只补缺与修正，不重排用户既有编号。

## 执行

1. **分组与编号**：按模块 → 链路 → 用例三级组织。编号 `TC-<模块缩写>-<三位序号>`，组内连续、不复用；沿用用户既有编号体系则照其续号。
2. **写前置条件**：只写「执行前必须已成立的状态」——账号状态、数据已造好、已进入某页面、某配置已开启。前置里出现动词即写成步骤了，移回步骤。
3. **写步骤**：一步一个动作，动词开头，按真实人为路径排序（打开 → 定位 → 输入 → 点击 → 观察）。不合并多动作成一步，不写「验证 X」当步骤，不写无具体次数的「多次点击」。状态描述不是动作——「保持为空」「停留在当前页」这类内容移到前置或预期。
4. **写预期结果**：与步骤同序号一一对应，且只写本层可判定的事实——文案原文、元素可见/置灰/可点、跳转到具体路径、列表条数、字段值。不写「是否发出请求」「是否落库」「接口返回什么」这类跨层断言，那些留给接口用例。不写「正常显示」「成功」「无误」。
5. **配数据**：步骤里直接写出具体取值并注明来源（已有账号/新建/接口造数）。页面上每个输入项都要有独立边界用例（空、上限、上限+1、特殊字符），不能用一条「必填校验」代表整个表单。边界用例一条只验一个边界。
6. **定优先级**：P1 主链路正向与资金数据类异常，P2 一般异常与边界，P3 交互细节与低频组合。团队用 P0–P2 时按 P1→P0、P2→P1、P3→P2 映射并在文首注明。
7. **自检**：步骤数与动作数一致；每条预期可判定真假且不跨层；前置无操作动作；每个输入项都有独立边界用例；编号连续无跳号；引用数据的用例都能在数据准备清单里找到条目。

## 输出格式

产物为单个 Markdown 文档，可直接另存为 `.md` 交付或入库。

- 文首写一级标题（产物名），下一行写 `> 来源：<上游产物或用户材料>｜生成：YYYY-MM-DD`
- 节标题统一用中文序号加固定名（一、xxx、二、xxx），名称不改，供下游按标题定位；模块级标题写「模块：<模块名>」
- 列表与表格用原生 Markdown，不用代码围栏包裹；代码围栏只包裹真正的代码
- 表格列序与列名、编号格式固定，不按现状重排
- 不输出 HTML、图片、Excel、CSV 或散装纯文本

按模块分组，一个模块一节一张表，标题写 `#### 模块：<模块名>（链路 <链路ID>）`。列序固定不调换：优先级紧跟用例标题，便于按等级筛选与排序；表头名称固定，便于下游 `web-automation-feasibility-analyzer` 按列名解析。下方 4 条为结构示例，真实产出按同一列序展开到该模块的全部用例。

### 二、编号规则

`TC-<模块缩写>-<三位序号>`，模块缩写取模块名首字母大写（LOGIN、ORDER、PAY）；模块内连续不跳号；沿用用户既有编号体系时据其续接，不重排既有引用。

### 三、数据准备清单

| 数据项 | 用途 | 状态 |
| :--- | :--- | :--- |
| 账号 test01 / 密码 Passw0rd! | TC-LOGIN-001/002/003/004 | 已有 |
| 密码为 32 位字符串的账号 test01 | TC-LOGIN-003 | [待准备] |
| 密码长度上限实际值 | TC-LOGIN-003/004 | [待确认] |

状态只取三种：`已有` / `[待准备]`（数据要造） / `[待确认]`（规则值未定，如长度上限、锁定阈值）。`[待确认]` 的值只登记在本表，用例正文写成「（按实际上限值）」这类指向，不编具体数字。

## 禁止

- 不把多个场景合并成一条用例，也不用一条用例覆盖多个边界取值。
- 不在 UI 用例里写跨层断言（是否发请求、是否落库、接口返回码），这类结论交给接口用例。
- 不编造未确知的提示文案与阈值数字；写成「（按实际替换）」并登记到数据准备清单的 `[待确认]`。
- 预期结果不得依赖「应该」「大概」「正常」这类不可判定的表述。
- 不虚构未提供的账号、地址、金额；缺失一律进数据准备清单标 `[待准备]`。
- 不输出自动化判断、脚本或覆盖统计——分池与编码是下游 Skill 的职责。
- 不重复添加用户编辑过的文档里的编号，也不因重写而打乱既有引用。
