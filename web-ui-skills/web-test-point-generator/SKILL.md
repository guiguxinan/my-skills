# Web 测试点生成

把链路节点和页面元素转成可验证的测试点，保证链路不断、表单项不漏。

## 输入

- 上游（优先）：`web-core-link-analyzer` 的「核心链路清单」，按链路 ID 与节点名对齐，用「关键节点」串展开逐节点测试点。
- 单独调用：业务说明、需求描述、页面原型/截图、已有用例表、目标模块名称。
- 只有链路名称没有节点时，先补出节点并标 `[假设]` 再推导。
- 只有页面截图时，先枚举页面上的字段、按钮、开关、列表操作、弹层，再逐项展开。

## 执行

1. **建节点验证矩阵**：对每个节点问五件事——入参有哪些、前置状态是什么、怎么触发、输出落到哪个页面或状态、下游依赖什么。答不出的就是待确认项。
2. **逐节点覆盖六类**，每类显式判断「有/无」，无则给理由：

   | 类型 | 覆盖内容 |
   | :--- | :--- |
   | 正向 | 端到端跑通 + 单节点正确；含最短路径与含可选环节的完整路径 |
   | 异常 | 必填缺失、格式非法、越权、数据不存在、重复提交、下游超时或失败、接口报错后的页面表现 |
   | 边界 | 空值、最短/最长长度、刚好等于上限、上限+1、0 与负数、小数精度、特殊字符（空格、emoji、引号、HTML/脚本）、超长文本、分页首页/末页/越界、金额最小/最大/等于阈值 |
   | 状态 | 合法迁移全枚举 + 非法迁移：跳过中间态、逆向回退、重复触发、并发改状态；以及各状态在页面上的可见差异（按钮禁用、标签颜色、操作列图标增减） |
   | 交互 | 校验提示、按钮可用/禁用、二次确认、加载态、空态、错误态、字段联动、显隐切换、弹层打开与关闭方式 |
   | 权限 | 不同角色对同一页面的可见性、可操作性、越权访问、菜单是否出现 |

3. **表单项必查边界**：页面上每个输入项都要有独立边界测试点，不允许用一条「必填校验」代表整个表单；最少给出长度上下限、格式非法、特殊字符三组。下拉/单选/多选/日期区间单独列出选项集合与默认值。
4. **链路级补充**：端到端正向一次；断链（中途关闭、返回、刷新、重复进入、换端继续）各一次；跨链路依赖失效（如登录态过期后继续操作）各一次。
5. **去重与追溯**：每个测试点挂到一个链路 ID 与节点；挂不上的要么补节点要么删。同一规则的多种表现合并为一条，用「分别验证」表述。
6. **定优先级**：P1 主链路正向与资金/数据类异常，P2 一般异常与边界，P3 交互细节与低频权限组合。

## 输出格式

产物为单个 Markdown 文档，可直接另存为 `.md` 交付或入库。

- 文首写一级标题（产物名），下一行写 `> 来源：<上游产物或用户材料>｜生成：YYYY-MM-DD`
- 节标题统一用中文序号加固定名（一、xxx、二、xxx），名称不改，供下游按标题定位；模块级标题写「模块：<模块名>」
- 列表与表格用原生 Markdown，不用代码围栏包裹；代码围栏只包裹真正的代码
- 表格列序与列名、编号格式固定，不按现状重排
- 不输出 HTML、图片、Excel、CSV 或散装纯文本

- 链路：CL-01 核心下单支付（节点：①确认页 → ②选择地址 → ③提交订单 → ④支付结果页）

## 脚本

`scripts/` 下的辅助脚本，用于解析上游链路清单与自查覆盖情况：

| 脚本 | 用途 |
| :--- | :--- |
| `scripts/parse_links.py` | 把上游 01 文件的链路小节解析成结构化 JSON（编号、名称、类型、触发条件、角色、节点串、主/分支、来源依据），节点按圈号 ①②③ 切分。避免人工誊抄漏字段。 |
| `scripts/coverage_check.py` | 自查测试点清单：每条 TP 是否挂了链路 ID 与节点、是否带六类标签；`--table` 直接生成「覆盖自查」表骨架。标签体系不同时用 `--categories` 指定。 |
| `scripts/mdutil.py` | Markdown 通用读写工具库（表格解析、章节替换、代码块提取、标题统计）。 |

用法示例：

```bash
python scripts/parse_links.py ../../test-design/web/01-核心链路清单.md --json links.json
python scripts/coverage_check.py ../../test-design/web/02-测试点清单.md --table
```

## 禁止

- 不写执行步骤与预期结果，测试点只描述「验证什么」，落到操作是 `web-test-case-writer` 的职责。
- 不编造链路之外的业务规则；规则不确定时进「待确认」而不是按常识补。
- 不用多条同质测试点充数，也不把「必填、长度、格式」压成一条。
- 不给没有链路归属的散点测试点。
- 不按「页面上大概有哪些字段」猜元素；没看到的控件不列。
